# مجالس — منصة إدارة المجالس العلمية التربوية

منصة عربية RTL تعمل كتطبيق ويب مثبَّت على الهاتف (PWA). تدير مجلسًا عامًا للطلاب،
ومجلسًا خاصًا هو فريق العمل الذي يدير التواصل والحضور والرسوم والتكاليف والتفريغ،
وتُخرج تقريرين في كل مجلس: تقرير عن الطلاب للشيخ، وتقرير عن أداء الفريق نفسه.

## التشغيل في خمس خطوات

### ١. أنشئ مشروع Supabase

ادخل [supabase.com](https://supabase.com) وأنشئ مشروعًا جديدًا، ثم من
**Project Settings → API** خذ قيمتين: `Project URL` و`anon public key`.

### ٢. شغّل ملفات قاعدة البيانات بالترتيب

**لمشروع جديد:** من **SQL Editor** في Supabase الصق محتوى `supabase/setup_all.sql` كاملًا واضغط Run مرة واحدة.
يجمع الملفات الستة أدناه بالترتيب في معاملة واحدة، وإعادة تشغيله آمنة.

أو شغّل الملفات منفردة بهذا الترتيب (لقاعدة قائمة طُبّق عليها بعضها):

| الترتيب | الملف | ما يفعله |
| --- | --- | --- |
| ١ | `supabase/migrations/0001_schema.sql` | ١٦ جدولًا، الأنواع، الفهارس، منع حذف الإيصالات، سجل التدقيق |
| ٢ | `supabase/migrations/0002_rls.sql` | سياسات الحماية: لا يقرأ المسؤول إلا نطاقه |
| ٣ | `supabase/migrations/0003_views.sql` | مناظر التقارير والأرصدة والأداء |
| ٤ | `supabase/seed.sql` | قوالب رسائل واتساب الستة |
| ٥ | `supabase/migrations/0004_critical_fixes.sql` | إضافة طالب بلا حساب، وتضييق صلاحيات الحذف والرسوم والنشر |
| ٦ | `supabase/migrations/0005_scoping_fees.sql` | حصر صلاحيات المدير بمجلسه، ونزاهة الإيصالات والقيد العكسي، والإعفاء |
| ٧ | `supabase/migrations/0006_api_grants.sql` | صلاحيات واجهة البيانات: المستخدم المسجَّل فقط، والزائر لا يصل لشيء |
| ٨ | `supabase/migrations/0007_hardening.sql` | تقوية: الأدوار للمدير وحده، سجل تدقيق بمجلسه، آخر مدير لا يُسحب، حدود المدخلات، منع تنفيذ الدوال للزائر |
| ٩ | `supabase/migrations/0008_members_scope.sql` | الأعضاء: اسم المستخدم والتعطيل، المجموعات، نطاق كل دور (يشمل الشيخ) |
| ١٠ | `supabase/migrations/0009_wird_levels.sql` | مستويات الأوراد والعبادات والمتابعة اليومية وتقرير الالتزام |
| ١١ | `supabase/migrations/0010_attendance_fees.sql` | وقت الحضور ومن عدّل، تقرير الحضور، الرسوم المستحقة والدفع الجزئي والإعفاء الجزئي |

بعد تعديل أي هجرة شغّل `npm run db:bundle` ليُحدَّث `setup_all.sql` (يفحصه الـ CI).

### ٣. اضبط المفاتيح

```bash
cp .env.example .env
# ثم افتح .env وضع الرابط والمفتاح
```

### ٤. شغّل محليًا

```bash
npm install
npm run dev
```

افتح `http://localhost:5173` وأنشئ أول حساب — يصبح ملفًا شخصيًا تلقائيًا.

### ٥. اجعل نفسك مديرًا

بعد إنشاء حسابك، افتح `supabase/bootstrap_admin.sql`، غيّر البريد واسم المجلس ومكانه وموعده في أوله،
ثم شغّله من SQL Editor مرة واحدة. ينشئ المجلس ويجعلك مديره، ويخبرك إن لم يجد حسابًا بهذا البريد.

بعدها كل شيء من داخل المنصة: الأدوار، النطاقات، الجلسات.

## النشر على Vercel

```bash
npx vercel
```

أضف متغيري البيئة `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY` في إعدادات المشروع على Vercel.
ملف `vercel.json` يوجّه كل المسارات إلى `index.html` حتى يعمل التنقل الداخلي (عدا `/api/`).

**لإضافة الأعضاء باسم مستخدم وكلمة مرور** أضف أيضًا `SUPABASE_SECRET_KEY` (المفتاح السري من
Supabase ← Project Settings ← API Keys، ويبدأ بـ `sb_secret_`) في متغيرات Vercel، **دون** بادئة `VITE_`،
ثم أعد النشر. يستخدمه الخادم `api/members.ts` وحده، ولا يصل للمتصفح أبدًا.

## الأعضاء والصلاحيات

- **الأعضاء** (لوحة الإدارة): المدير يضيف عضوًا باسمه واسم مستخدم وكلمة مرور، ويسند له دورًا أو أكثر.
  كلمات المرور يخزّنها Supabase Auth مجزّأة (bcrypt) ولا تُعرض بعد الحفظ. يدخل العضو باسم المستخدم مباشرة.
- **النطاق**: لكل دور (الشيخ، الحضور، الرسوم، التواصل، التكاليف والأوراد) إما «كل طلاب المجلس» أو مجموعات
  وطلاب محددون. العضو يرى ويتحكم في نطاقه فقط، والقاعدة تفرض ذلك على كل جدول.
- **المجموعات**: تُربط بالدور فيتبعها أعضاؤها الحاليون والقادمون تلقائيًا.
- **التعطيل**: يسحب كل الصلاحيات فورًا (في القاعدة) ويمنع الدخول (في Supabase Auth). لا يُدار حساب من له
  صلاحيات في مجلس آخر، ولا يعطّل المدير نفسه.
- **التسجيل الذاتي** = «طالب» دائمًا، ولا يكتسب أي صلاحية إلا بإسناد المدير.

## متابعة الأوراد

- عبادات مخصصة لكل مجلس بطريقة متابعة: تم/لم يتم، أو عدد، أو كمية.
- مستويات بأي عدد، ولكل مستوى عباداته وهدف كل منها (المستوى الأول: الصلوات؛ الرابع: الصلاة والأذكار والقرآن…).
- تعيين المستوى لطالب أو لمجموعة أو للجميع. النقل يغلق المستوى السابق ويحفظه في السجل، والسجلات القديمة تبقى
  منسوبة لمستواها القديم.
- الطالب يرى أوراد مستواه فقط ويسجلها يوميًا، ونسبة الالتزام تُحسب على ما طُلب منه هو في كل يوم.

## الحضور

الحالات الأربع مع وقت الوصول الفعلي بالدقيقة (يُسجَّل تلقائيًا ويمكن تعديله). كل تعديل يُختم باسم من أجراه ووقته،
ويبقى من سجّل أول مرة. تقرير لكل طالب ومجموعة وفترة في «التقارير».

## الهوية البصرية

لوحة هادئة وفخمة: أخضر داكن عميق (الأساس) وعاجي دافئ (الخلفية) وذهب خافت (اللمسة)، وألوان الحالة مخفَّضة التشبّع.
كلها في `tailwind.config.js` بأسماء Tailwind المعتادة، فتغيّر هوية كل الشاشات من ملف واحد. التنقل: شريط جانبي
بأيقونات قابل للطيّ على الشاشات الكبيرة، وشريط سفلي بأيقونات (و«المزيد») على الهاتف.

**الخطوط:** `Readex Pro` للنصوص و`Markazi Text` للعناوين (مفتوحة الترخيص OFL، محزَّمة مع الموقع بلا أي طلب خارجي).
لتبديلها غيّر `--font-sans` و`--font-display` في `src/index.css` فقط.
> **خط ثمانية:** ترخيصه يمنع استضافة ملفات الخط على أي خادم وتضمينه كملفات ويب، ويمنع تعديلها أو تحويل صيغتها
> (متوفر بصيغة OTF فقط وبتنزيل يتطلب بريدًا). لا يجوز استخدامه في الموقع دون إذن مكتوب من ثمانية: `Ask@thmanyah.com`.

**معاينة التصميم بلا خادم:** `npm run dev:design` يشغّل التطبيق ببيانات تجريبية (حساب مدير وهمي). أضف `?login` لشاشة الدخول.

## الأدوار

| الدور | المفتاح | ما يفعله |
| --- | --- | --- |
| الشيخ | `sheikh` | يرى التقارير، يضيف تكاليف، يعتمد الملخصات، يكتب ملاحظات خاصة. **لا يُسنِد أدوارًا** |
| مدير المنصة | `admin` | وحده يُسنِد الأدوار والنطاقات وينشئ الجلسات، وفوق ذلك كل ما للشيخ. آخر مدير في مجلس لا يمكن سحبه |
| مسؤول التواصل | `contact_officer` | قائمتي، رسائل واتساب، تسجيل نتيجة الاتصال |
| مسؤول الحضور | `attendance_officer` | كشف الحضور، يعمل بلا إنترنت |
| مسؤول الرسوم | `finance_officer` | التحصيل والإيصالات المرقّمة |
| مسؤول التكاليف | `tasks_officer` | شبكة المتابعة الملوّنة وأسباب التعثر |
| مسؤول التفريغ | `transcription_officer` | الملخص واستخراج التكاليف منه |
| عضو / طالب | `member` / `student` | تكاليفه وحضوره ورسومه فقط |

## ثلاث قواعد محفورة في الكود

1. **لا زر حفظ** حيث تُحرَّر البيانات القائمة — الحقول تُحفظ تلقائيًا بعد توقف الكتابة، مع مؤشر «تم الحفظ». (نموذج الإضافة يُرسَل مرة واحدة حتى لا يضيع آخر ما كُتب.)
2. **لا شاشة فارغة** — كل قائمة فارغة تحمل سطرًا يشرح الخطوة التالية.
3. **كل رقم قابل للضغط** — الضغط على «٩ متأخرين» يفتح أسماءهم.

## الحماية

الحجب يتم في قاعدة البيانات لا في الواجهة. مسؤول التواصل لا تعود له استعلامات عن
الرسوم أصلًا، ولو فتح أدوات المطور. والإيصال لا يُحذف: محاولة الحذف تُرفض من
قاعدة البيانات نفسها، والتصحيح يكون بقيد عكسي يبقى في السجل باسم من أجراه.

- **عزل المجالس:** المدير والشيخ لا يريان ولا يعدّلان إلا مجلسهما، ويشمل ذلك سجل التدقيق.
- **أقل صلاحية:** كل دور يكتب ما يخصه فقط (مسؤول التفريغ لا ينشر، مسؤول الحضور لا يحذف جلسة، مسؤول التواصل لا يرى الرسوم).
- **الزائر غير المسجَّل:** لا يقرأ ولا يكتب ولا ينفّذ دالة. التسجيل مفتوح، لكن الحساب الجديد لا يرى شيئًا حتى يُضمّه المدير.
- **سجل التدقيق:** يكتبه التريجر وحده، ولا يُعدَّل ولا يُحذف من أحد حتى من SQL.
- **الواجهة:** سياسة `CSP` صارمة ورؤوس أمان في `vercel.json` (لا سكربت مضمّن ولا `eval` ولا اتصال إلا بـ Supabase)، وأخطاء الخادم تُترجم لرسائل عربية بلا تسريب تفاصيل داخلية.
- **توصيات في لوحة Supabase** (لا يمكن ضبطها من الكود): فعّل **Confirm email**، ورفع الحد الأدنى لكلمة المرور إلى ٨ في Authentication ← Providers ← Email، وفعّل **Leaked password protection**، وأضف رابط موقعك في URL Configuration.

## الاختبارات

```bash
npm test               # كل شيء: وحدة + مكوّنات + أمان ساكن (+ قاعدة البيانات إن ضُبط الرابط)
npm run test:unit      # وحدة ومكوّنات فقط، لا تحتاج قاعدة
npm run typecheck      # الكود والاختبارات
npm run db:check       # هل setup_all.sql محدّث؟
```

اختبارات القاعدة والصلاحيات تحتاج Postgres فارغًا (تُنشئ قاعدة مؤقتة وتحذفها):

```bash
TEST_DATABASE_URL=postgres://postgres:postgres@localhost:5432/postgres npm run test:db
```

تغطي: الزائر، وعزل المجالس (قراءة وكتابة، لكل جدول ومنظر)، وصلاحيات كل دور، والإيصالات والقيد العكسي،
والملخصات، وآخر مدير، وسجل التدقيق، وحدود المدخلات، وإعادة تشغيل الملف المجمَّع. وكل دفعة تُجرَّب على
بيئة «أسوأ حالة» تمنح الزائر كل شيء افتراضيًا ليتأكد أن الهجرات تسحبه.
ويشغّل `.github/workflows/ci.yml` كل ذلك مع فحص ثغرات الحزم عند كل push.

## الرسوم

- **رسوم مستحقة** لكل طالب بفترتها (من خطة أو بمبلغ مخصص)، أو «تطبيق الخطة على الطلاب» دفعة واحدة؛ نفس
  الخطة لنفس الفترة لا تُحسب مرتين.
- **دفع كامل أو جزئي** بدفعات متعددة، والمتبقي يُحسب تلقائيًا. القاعدة ترفض أي دفعة تتجاوز المتبقي، وكل محاولة دفع
  تحمل معرّفًا فريدًا فلا يسجّل الضغط المزدوج الدفعة مرتين.
- **إعفاء كلي أو جزئي** بسبب مكتوب، ولا يُسمح بإعفاء يجعل المدفوع أكبر من الصافي.
- **الحالة**: مسددة، مسددة جزئيًا، غير مسددة، معفى (أو «لا رسوم»).
- الإيصال لا يُعدَّل ولا يُحذف. الخطأ يُصحَّح بقيد عكسي يساوي سالب الإيصال ويلزمه سبب ويعيد المتبقي.
- نُقلت الخطط والإعفاءات والدفعات القديمة تلقائيًا إلى هذا النظام بلا فقد.

## واتساب

تُستخدم روابط `wa.me` المجانية — لا واجهة برمجية مدفوعة. الضغط على زر الواتساب
يفتح التطبيق برسالة معبّأة من قالب، والمستخدم يراها ويعدّلها قبل الإرسال.
القوالب تدعم المتغيرات: `{اسم_الطالب}` `{اسم_المجلس}` `{التاريخ}` `{المكان}` `{رابط_الملخص}`.

## العمل بلا إنترنت

قاعات المجالس كثيرًا ما تكون ضعيفة الشبكة، فالتطبيق نفسه يُحفظ على الجهاز (`public/sw.js`) ويفتح بلا إنترنت
بعد أول زيارة، وكشف الحضور يُكتب في IndexedDB محليًا ويُزامن تلقائيًا عند عودة الاتصال، ويظهر في الشريط
العلوي عدّاد «بانتظار المزامنة». ما ترفضه قاعدة البيانات لا يُعاد إلى ما لا نهاية، بل يظهر في عدّاد
«تعذّر رفعها». وعند الخروج من الحساب تُحذف عمليات هذا الحساب من الجهاز بعد التنبيه.

## استخراج التكاليف من الملخص

في محرر الملخص، اكتب كل تكليف في سطر بهذه الصيغة:

```
- [عبادة] ورد يومي من سورة البقرة
- [بحث] بحث في معنى الإخلاص
```

ثم اضغط «استخراج التكاليف» فتدخل شاشة التكاليف تلقائيًا بلا إدخال يدوي.
